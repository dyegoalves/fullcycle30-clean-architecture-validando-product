Título: Clean Architecture: Validação Desacoplada na Entidade Product

Objetivo Agora que aprendemos a criar um processo de validação desacoplado, sua missão é replicar esse comportamento para a entidade Product. Você deve retirar as regras de validação diretas da entidade e delegá-las a uma classe validadora especializada, minimizando o acoplamento no seu domínio.

Tecnologias e Ferramentas

Linguagem: TypeScript

Padrão: Validator Pattern / Validation Factory

Testes: Unitários

Base do Projeto: Repositório Template (Obrigatório)

Estrutura Base (Obrigatória) Para realizar este desafio, é obrigatório continuar utilizando o código base do curso (ou a evolução do desafio anterior).

https://github.com/devfullcycle/fc-clean-architecture.git

Requisitos Técnicos
Criação do Validator: Implemente uma classe de validação específica para a entidade Product ( ProductYupValidator), seguindo o padrão de interfaces definido no módulo.

Desacoplamento: Refatore a entidade Product para que ela não valide os dados diretamente (com if/else soltos), mas sim utilize o validador que você criou.

A entidade deve chamar o validador, que por sua vez deve preencher o Notification (implementado no desafio anterior) em caso de erros.
Integridade: O comportamento externo da entidade não deve mudar. Ela deve continuar rejeitando dados inválidos, mas agora internamente o processo deve ser delegado.

 

Critérios de Testes (Regressão)

Testes Passando: Como se trata de uma refatoração, é crucial garantir que todos os testes existentes continuem passando.

O objetivo é alterar a implementação (o "como"), sem quebrar o comportamento (o "o quê").

Entregável

Link do Repositório: O link para o seu repositório no GitHub contendo a implementação.

README: Instruções de execução dos testes.

Regras de Entrega
